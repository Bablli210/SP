# Serious Play website

The production site for Serious Play: work first, show don't tell. Astro static site, no server needed.

## Run it

```sh
cd site
npm install
npm run dev       # http://localhost:4321
npm run build     # static site in dist/
npm run preview   # serve dist/ locally
npm run check     # type check
```

Node 22 or newer.

## Pages

| Path | What it does |
|---|---|
| `/` | The ring: featured projects on a draggable, momentum ring. Scroll, drag or use the arrow keys; switch to the index list; open a plate to morph into its case study. |
| `/work/` | Every project, filterable by discipline and sector, as a grid or a list with a hover preview. |
| `/work/<slug>/` | Case study: hero, facts, the finding, gallery, optional film, credits, next project. The cover morphs in from wherever you clicked it. |
| `/studio/` | Intro, the five-step method, people, clients and press. |
| `/services/` | Disciplines as an accordion, each showing the projects that use it and a link to the filtered work index. |
| `/lab/` | Experiments and motion studies in a masonry grid with a full-screen viewer. |
| `/contact/` | Brief form, direct email, Instagram. |
| `/404` | Five covers spilled across the foot of the screen, drifting with the pointer; each one links to its project. |

## Swapping placeholders for the real thing

Everything the studio needs to replace is in three places. Anything in `[square brackets]` is a placeholder.

**1. Projects** (`src/content/projects/<slug>.md` and `src/assets/work/<slug>/`)

- One Markdown file per case study. The file name is the URL (`halwa-house.md` → `/work/halwa-house/`).
- Images go in `src/assets/work/<slug>/`. Keep the same file names and you only need to swap the files; change the names and update the paths in the Markdown.
- Sizes that work well: cover 1600×2000 (4:5); `wide` and `full` gallery images 2400×1500; `half` and `offset` 1200×1500. Bigger is fine, Astro makes the smaller versions.
- `featured: true` puts a project on the home ring, sorted by `order`. `no` is the three-digit archive number, and the work index sorts by it.
- `accent` is the project's one colour on its case study.
- `finding` is the single sentence of prose on a case study. Keep it to one fact or insight.
- `film` (optional): `src` is a path under `public/` (e.g. `/films/halwa-house.mp4`) and `poster` an image in the project folder.
- `heroTone: dark` for a dark cover: the header's text turns paper while it sits over the case study's hero (the default is `light`).
- Projects and lab entries still marked `placeholder: true` are left out of the live site once PLACEHOLDER_CONTENT (`src/data/site.ts`) is false, and the build lists them. Delete the line once the project is real.

**2. Lab** (`src/content/lab/*.md` and `src/assets/lab/`)

One Markdown file and one image per entry. `loop` is an optional muted mp4 in `public/` that plays on hover.

**3. Studio facts** (`src/data/site.ts`)

Email, Instagram, city and time zone (shows local time on Contact), the method, people, clients, press and careers.

Studio portraits and method images live in `src/assets/studio/`.

The placeholder images were generated by `scripts/make-placeholders.mjs`. Once real images are in, don't run it again: it overwrites them.

## The contact form

Copy `.env.example` to `.env` and set `PUBLIC_FORM_ENDPOINT` to any form backend that accepts a POST (Formspree, Basin, a serverless function). Left empty, the form opens a pre-filled email to the studio instead, so it works from day one.

## Launch checklist

- [ ] Real projects, lab entries, studio facts and images in; no `[brackets]` left (`grep -rn "\[" src/data src/content`).
- [ ] `PLACEHOLDER_CONTENT = false` in `src/data/site.ts`. This removes the preview notice and lets search engines in (`robots.txt`).
- [ ] `PUBLIC_FORM_ENDPOINT` set, and a test brief received.
- [ ] `site` in `astro.config.mjs` matches the real domain (it drives canonical URLs, the sitemap and social cards).
- [ ] Replace `public/og.jpg` (1200×630) with a real social card.
- [ ] `npm run check` and `npm run build` both clean.

## Deploying

The build is a folder of static files (`dist/`), so any static host works. On Vercel or Netlify: root directory `site`, build command `npm run build`, output `dist`, and add `PUBLIC_FORM_ENDPOINT` as an environment variable.

## How it's built

- **Motion:** one easing family (`--ease`, `--ease-out` in `src/styles/global.css`). Every interaction is a rAF loop that lerps toward a target and stops when settled, animating only transform and opacity. Smooth scroll is Lenis (`src/scripts/motion.ts`). Everything respects reduced motion.
- **Page transitions:** Astro's ClientRouter with the View Transitions API. A project's cover carries the same `transition:name` everywhere it appears once on a page (`plateName()` in `src/lib/work.ts`), so it morphs between pages.
- **Scripts per page:** wrap setup in `onPage(() => { …; return cleanup })` from `src/scripts/motion.ts`. Scripts stay loaded across navigations, so setup must return early when its page isn't showing.
- **Images:** always through `src/components/Media.astro`, which serves responsive, compressed versions.
- **Art direction:** paper, bone, concrete and ink carry every page; one accent per screen. Type roles are `.display`, `.serif`, `.label` and `.ui`. See `BRIEF.md` for the full rules.

## Helper scripts

- `scripts/snap.cjs <url> <out> [--full] [--reduced]`: desktop and phone screenshots with console errors and overflow checks (needs Playwright).
- `scripts/make-placeholders.mjs`: regenerates the placeholder images (see the warning above).
- `node scripts/make-icons.mjs`: regenerates `public/apple-touch-icon.png` and `public/favicon.ico` after a change to `public/favicon.svg`.
